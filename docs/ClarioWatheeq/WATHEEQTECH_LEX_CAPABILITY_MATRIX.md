`Aligned` means the repository has a coherent executable path and deterministic evidence. `Conditional` means that path is internally coherent but final production proof depends on a live provider, deployed topology, performance/recovery exercise, or completion of the intentionally partial public API contract. It does not mean a fake or silently successful implementation was accepted.

## Evidence conventions

- `FE`: `frontend/src/app/(dashboard)/lex` (70 `page.tsx` route entries) and shared Lex components.
- `Client`: `frontend/src/lib/enterprise/api.ts` plus domain clients under `frontend/src/lib/lex`.
- `BE`: `backend/internal/lex/handler/routes.go`, services, repositories, monitors, consumers, and `backend/cmd/lex-service`.
- `Contract`: `docs/api/watheeq-lex-service.openapi.yaml` and `docs/api/watheeq-lex-api-inventory.md`.
- `DB`: `backend/migrations/lex_db` (85 ordered up/down pairs at audit time), with cross-domain IAM/workflow/audit migrations where named.
- Both `/api/v1/lex` and `/api/v1/watheeq` are gateway aliases and require the `app.watheeq` entitlement.

## Coverage boundary

The matrix traces the complete implemented product by capability, not by pretending that the phase-1 OpenAPI file is complete. The contract gate now proves three separate facts: all 122 declared operations exist, all ten required drafting operations remain declared and registered, and 502 additional registered operations are explicitly outside the current public contract boundary. Contract expansion is tracked in `WATHEEQTECH_LEX_OPEN_ISSUES.md`.
